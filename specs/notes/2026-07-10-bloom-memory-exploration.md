# Bloom-Filter Memory Exploration — Right-Sizing vs. Non-Residency (2026-07-10)

**Status: measured and decided; right-sizing only was selected and filed as [#302](https://github.com/bluesky-social/jetstream/issues/302) and [#303](https://github.com/bluesky-social/jetstream/issues/303).** The analysis found blooms were sized by event counts but populated with DIDs, substantially over-allocating memory; using persisted distinct-DID counts offered predictable savings. On-demand non-resident blooms were rejected because right-sizing reduced the benefit while adding I/O and latency complexity. The key code reference was `segment/bloom.go`. GitHub implementation: [PR #304](https://github.com/bluesky-social/jetstream/pull/304), [PR #306](https://github.com/bluesky-social/jetstream/pull/306).
