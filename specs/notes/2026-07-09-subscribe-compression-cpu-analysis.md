# `/subscribe` Wire Compression: CPU, Ratio, and Fanout Analysis (2026-07-09)

This historical measurement compared uncompressed, per-message deflate, and dictionary-based compression using corpus and live/cold fanout tests. It found meaningful bandwidth savings but server CPU that scaled per subscriber because payloads were recompressed independently; dictionary retraining improved ratio but did not remove the fanout cost. The recommendation was aimed at `/subscribe-v2` while leaving legacy `/subscribe` unchanged. References were `internal/subscribe/compress.go`, `internal/subscribe/replay.go`, `internal/client/live.go`, `docs/README.md`, and `cmd/client/loadtest.go`.
